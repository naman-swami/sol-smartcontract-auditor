# Explainability Architecture: sol-smartcontract-auditor

SolAudit — EVM Smart Contract Vulnerability & Reentrancy Hunter implements a transparent, auditable decision pipeline designed to satisfy regulatory, compliance, and operational verification requirements.

## Decision Reasoning
Every analytical conclusion generated by sol-smartcontract-auditor decomposes into a chain-of-thought provenance graph:
1. **Input Telemetry Validation**: Ingestion parameters are checked against physical, legal, or statistical boundary bounds.
2. **Deterministic Constraint Evaluation**: Hard logical rules, statutory mandates, or physical laws are evaluated prior to probabilistic heuristics.
3. **Probabilistic Multi-Factor Scoring**: Weighted scoring models synthesize multiple continuous signals into objective indices.
4. **Counterfactual Exploration**: Alternative hypotheses are evaluated to ensure conclusions are robust against edge case mutations.

## Data Sources and Inputs Used
The agent operates over heterogeneous verifiable input modalities:
- Direct API payloads conforming to strict JSON Schema contracts.
- High-frequency time-series telemetry streams, sensor feeds, or transactional ledgers.
- Verified reference domain corpora (standards documents, regulatory registers, historical baselines).
- Runtime context parameters supplied by human operators or orchestration workflows.

## Confidence Scoring Methodology
Confidence scores ($C \in [0.0, 1.0]$) are formulated mathematically as a composite harmonic mean of three components:
- **Telemetry Completeness ($S_{comp}$)**: Ratio of required vs observed input features ($S_{comp} = \frac{N_{present}}{N_{total}}$).
- **Model Consensus ($S_{cons}$)**: Agreement variance across ensemble evaluation prompts ($S_{cons} = 1.0 - \sigma_{ensemble}^2$).
- **Historical In-Distribution Proximity ($S_{dist}$)**: Mahalanobis distance between current input vector and historical training distribution.
$$C = \frac{3}{\frac{1}{S_{comp}} + \frac{1}{S_{cons}} + \frac{1}{S_{dist}}}$$

## Source Attribution Protocol
All factual claims, regulatory citations, and diagnostic thresholds cite authoritative origins:
- Cryptographic SHA-256 hashes of underlying datasets or telemetry logs.
- Standardized taxonomy codes (e.g., ISO, IEEE, MedDRA, ACMG, ATA, or FinCEN standards).
- Line-level trace references linking output properties directly to raw payload attributes.

## Bias Awareness
To prevent systematic distortions:
- Demographic, geographic, and institutional proxies are explicitly stripped prior to merit or risk scoring.
- Disparate impact ratios and demographic parity statistics are continuously computed across cohort evaluations.
- Temporal bias decay functions down-weight stale historical anomalies that no longer reflect contemporary reality.

## Limitation Taxonomy per Domain
The agent enforces strict operational limits within its domain (Cybersecurity):
- **Sensor Loss & Epistemic Gaps**: When telemetry dropout exceeds 15%, the agent refuses deterministic prediction and enters safe fallback mode.
- **Out-of-Distribution Inputs**: Inputs lying outside calibrated dynamic ranges trigger immediate human-in-the-loop escalation.
- **Zero-Day & Unprecedented Scenarios**: Completely novel patterns lacking historical precedent are flagged as unclassified anomalies.

## Uncertainty Quantification Approach
Uncertainty is partitioned into Aleatoric and Epistemic components:
- **Aleatoric Uncertainty**: Inherent measurement noise modeled via heteroscedastic predictive variance bounds.
- **Epistemic Uncertainty**: Knowledge deficit modeled via Monte Carlo dropout sampling and temperature variation across agent inferences.
- When total uncertainty exceeds established tolerance thresholds, automated action dispatch is locked and requires human supervisor override.
